# AGENTS.md

Инструкции для AI-агентов, работающих над этим репозиторием.

## О проекте

Браузерная игра «три в ряд» (match-3) для ПК и мобильных устройств.
Игрок меняет местами две соседние фишки; линия из 3+ фишек одного цвета объединяется
в ячейку уровнем выше, сверху падают новые, возможны каскады.

Главная особенность — **система объединения ячеек**: каждое совпадение превращает фишки
в ячейки более высокого уровня, которые приносят намного больше очков.

## Стек

- **TypeScript** (strict)
- **Phaser 3** — движок (сцены, твины, ввод, звук)
- **Vite** — сборка и dev-сервер
- **Vitest** — тесты
- **ESLint + Prettier**
- npm

## Команды

```bash
npm install
npm run dev        # dev-сервер, здесь же доступен редактор уровней
npm run build      # сборка в dist/ — статические файлы, пути относительные (кладутся в любую папку)
npm run preview    # проверка сборки из dist/ на http://localhost:4173
npm run test       # Vitest
npm run lint
npm run typecheck  # tsc --noEmit
npm run simulate   # бот играет партии и считает очки: [-- <партий> <ходов> [цены] [режимы]]
npm run levels     # боты играют уровни кампании: [-- <партий> [этаж] [--fresh]]
npm run levels:history  # версии уровня и замеры: -- 4-10; откат к версии: -- 4-10 <хеш>
npm run levels:tune  # подгонка ходов и звёзд этажа под кривую сложности: -- <партий> <этаж> [--only=9,10]
npm run levels:humans  # ходы бота против ходов людей и подбор его мастерства: -- <выгрузка level_moves.json> [--grid]
npm run build:function   # сборка серверной функции в supabase/functions/smooth-handler/index.ts
npm run deploy:function  # сборка и выкладка функции в Supabase (нужен npx supabase login)
```

Задача считается выполненной, только когда проходят `test`, `lint` и `typecheck`.

  разойдутся, результаты перестанут проходить проверку. Сборка функции лежит в репозитории,
  CI не даст опубликовать сайт, если она устарела (развёрнутую версию CI не проверяет).

## Режим игры

- Игра состоит из **уровней с целями**.
- **Ограничение по ходам** задаётся уровнем, когда оно нужно (у уровня может не быть лимита).
  Пока уровней нет, временная партия ограничена 35 ходами (см. «Партия: 35 ходов и финал»).
- Размер поля, набор цветов, форма поля и препятствия задаются **в описании уровня**.

### Меню и сложность (пока уровней нет)

- При запуске — **главное меню**: заголовок, кнопки **«Кампания»** и **«Правила игры»** того же вида,
  что и кнопки сложности, отступ в полтора интервала между кнопками, затем свободная игра
  с выбором сложности.
- **«Сброс прогресса кампании»** — на экране правил, в одном ряду с «Назад» (`ui/resetProgressButton.ts`):
  первое нажатие просит нажать ещё раз, второе в течение 3 с стирает звёзды и траты всех уровней
  (открыт остаётся только 1-1) и забывает код переноса — иначе при следующем сохранении прогресс
  вернулся бы с сервера (`resetCampaignProgress`, `forgetTransferCode`).
- **«Тестовый уровень»** — третья кнопка в ряду под правилами (рядом с «Назад» и сбросом прогресса): партия
  по правилам Детского (3 цвета, 35 ходов, покупка за очки, финал), но фишки — кристаллы второго набора художника
  (`public/assets/crystals/`, `view/crystalArt.ts`): **1 уровень — неогранённый камень** (без сияния, чуть покачивается),
  **2 — грубый кристалл** (мягкий белый ореол, одна блёстка), **3 — огранённый самоцвет** (ореол ярче, две блёстки).
  Фишка — 84% клетки по центру, поле — тёмная шахматка, как у всей игры. Синее поле образца художника
  (фон `#6686BD` с каймой и полупрозрачные плитки `cell.png`) владелец убрал; оно в коде за `CRYSTAL_BLUE_FIELD`. Кристаллы нарисованы голубыми; красный и зелёный —
  перекраска `HUE_MAPS` со сдвигом на разницу оттенков рисунка (~200°) и прежнего листа (233°). Ореол — размытый
  белый силуэт фишки, у каждой фишки своя фаза анимации. Яркость и насыщенность по просьбе владельца (`TONES`):
  все три цвета — с яркостью и насыщенностью рисунка, как синие. Картинки грузятся только для этого уровня (`GameScene.preload`).
  Прежний набор (камень, ромб и кристалл с листа, `view/sparkleGems.ts`, `public/assets/sparkle/`) в коде остался:
  из него берутся перекраска и блёстки.
  Без билета: в общую таблицу и статистику партий не попадает; «← Правила» и «Меню» в конце возвращают на экран правил.
- «Правила игры» — отдельный экран (`scenes/RulesScene.ts`, панель — `ui/RulesPanel.ts`)
  с кнопкой «Назад». Правила — в две колонки со значками фишек. Слева — комбинации: рисунки всех фигур,
  что они дают на каждом уровне и сколько очков (`ui/matchFigures.ts`). Справа — спецфишки и их комбо. Числа берутся из `core/config.ts`
  и `matchPoints`, поэтому меняются вместе с игрой; но подписи спецфишек и комбо написаны
  вручную: изменил их механику — поправь подпись.
- Обе колонки правил стоят на одной сетке, значки и подписи одного размера. Тест сверяет фигуры с настоящим
  разбором хода; появилась новая фигура — добавь её в `MATCH_FIGURES`.
- Сложность задаёт число цветов на поле 10×10:

  | Сложность | Цветов |
  | --------- | ------ |
  | Детский   | 3      |
  | Лёгкий    | 4      |
  | Средний   | 5      |
  | Сложный   | 6      |
  | АД        | 7      |

- На кнопке сложности — кружки её цветов и рекорд (лучший результат её таблицы лидеров).
- В заголовке игры — название сложности («Три в ряд · Средний»).
- **У каждой сложности своя таблица лидеров.**

### Звуки

- Звуки синтезируются кодом через Web Audio (`src/audio/synth.ts`), без файлов. Фишки — кристаллы, поэтому основа —
  звон (негармоничные обертоны) и блёстки; взрывы — звон осколков, а не грохот. Владелец забраковал «электронное»
  и высокое: мелодии от до второй октавы (523 Гц), у звона есть щелчок удара, обертоны раздвоены (живые биения),
  верх срезан выше 6,5 кГц, всё звучит с лёгкой реверберацией; скользящих синусов нет — вместо них шорох воздуха (`swell`).
- **Отбор звуков** — страница `sound-lab.html` (только `npm run dev`: http://localhost:5173/sound-lab.html, в сборку
  не попадает): у каждого действия три варианта (`src/audio/soundCatalog.ts`) — а хрусталь, б мягкий (как маримба из камня), в искры.
  Владелец слушает и называет подходящие («5б»); каждый звук не длиннее 1,5 с. Прошедшие отбор переносятся в игру.
- **Звуки в игре** — выбранные варианты лаборатории (поле `chosen` в каталоге; `src/audio/gameSounds.ts`). Какой звук
  играть по шагу хода, решает `StepSoundTracker` (`src/audio/stepSounds.ts`, без браузера, покрыт тестами): у него
  своя копия поля — по ней видно, какие спецфишки сработали в очищенных клетках; лёд, золото и выполненные цели —
  по разнице прогресса уровня между шагами. Комбо двух спецфишек звучит звуком пары (16.x), взрывы самих спецфишек
  в первом ударе при этом не озвучиваются. Один и тот же звук не чаще раза в 60 мс. Прочее: выделение фишки, неверный
  обмен, перемешивание, подсказка, покупка, «осталось 5 ходов», звёзды по одной в итоге уровня, поражение, конец
  свободной игры, кнопки меню (`createMenuButton`). Звук создаётся по первому действию игрока (так требует браузер).
  **Выключатель** — значок динамика справа вверху в меню и в игре (`ui/soundToggle.ts`), хранится в `match3.soundOff`.
  Под сомнением у владельца (решить, услышав в игре): приземление фишек 4е, радуга 14а и комбо с радугой.
- **Металл** (цепь, звенья) звучит по отдельному яркому пути `Synth.bright` — без среза высоких частот и почти без
  отзвука: со срезом металл звучал как мягкий хрусталь. Цепь (20) повторяет образец владельца: ~60 ударов звеньев
  в секунду, звон — гроздь частот 11–14 кГц (`CHAIN_LINK_MODES`), громкость нарастает и обрывается (`shakenChain`);
  по просьбе владельца вся цепь на октаву ниже образца и на 25% громче (`CHAIN_PITCH`, `CHAIN_LOUD`).

## Правила игры

### Базовые

- Обмен — только с соседней по стороне клеткой. Обмен без совпадения откатывается и не тратит ход.
- Совпадение — 3+ фишки одного цвета **и одного уровня** по горизонтали или вертикали,
  а также **квадрат 2×2** — на **любом уровне**. Фигуры с общими клетками сливаются в одну группу.
- Группа считается по числу клеток любой формы (квадрат 2×2 — 4 клетки); 6 и больше → **как 5**.
- После удаления: гравитация вниз → заполнение сверху → снова поиск совпадений (каскад).
  Фишки **пролетают сквозь дыры** в поле. Новые фишки — 1 уровня, случайного цвета,
  совпадения среди них допускаются (из них и получаются каскады).
- Стартовое поле — без готовых совпадений и хотя бы с одним возможным ходом.
- Если ходов нет — перемешать поле:
  - «ходов нет» — нет обмена двух обычных фишек, дающего совпадение (спецфишки ходом
    не считаются); проверка — после каждого хода и после покупки спецфишки;
  - переставляются **все** фишки и ячейки любых уровней **и спецфишки**; дыры и препятствия кампании (лёд, камни,
    сундуки, короны) остаются на месте;
  - после перемешивания нет готовых совпадений и есть хотя бы один ход. Если перестановкой
    этого не добиться — отдельные фишки 1 уровня меняют цвет, пока ход не появится
    (ячейки 2–3 уровня и спецфишки не перекрашиваются);
  - перемешивание хода не тратит.

### Совпадения: сразу награда

Любое совпадение **сразу, без выбора игрока** превращается в награду. Размер группы считается
по числу клеток любой формы (квадрат 2×2 = 4 клетки), **6 и больше — как 5**:

| Совпадение | Награда                                                                 | Очки за группу                     |
| ---------- | ----------------------------------------------------------------------- | ---------------------------------- |
| 3 × 1 ур.  | 1 ячейка 2 уровня                                                       | 3 × 10 = 30                        |
| 4 × 1 ур.  | **2 ячейки 2 уровня**                                                   | 4 × 10 = 40                        |
| 5+ × 1 ур. | **1 ячейка 3 уровня**                                                   | 10 за клетку                       |
| 3 × 2 ур.  | 1 ячейка 3 уровня                                                       | 3 × 50 = 150                       |
| 4 × 2 ур.  | **2 ячейки 3 уровня**; если это прямая линия — ещё **ракета** вдоль неё | 4 × 50 = 200                       |
| 5+ × 2 ур. | **Мега-бомба**                                                          | **450** (как за 3 ячейки 3 уровня) |
| 3 × 3 ур.  | **Мега-бомба**                                                          | 3 × 150 = 450                      |
| 4 × 3 ур.  | **Радуга**                                                              | 4 × 200 = 800                      |
| 5+ × 3 ур. | **2 радуги** рядом                                                      | 250 за клетку                      |

- **Фигура из 7 клеток** — линия из 5 и ещё две клетки от её середины поперёк: обе в одну сторону
  или по одной в каждую (крест); поворот и сторона не важны. 7 клеток другой формы считаются как 5+.

  | Фигура    | Награда               | Очки за группу                  |
  | --------- | --------------------- | ------------------------------- |
  | 7 × 1 ур. | **2 ячейки 3 уровня** | **350**                         |
  | 7 × 2 ур. | **2 радуги** рядом    | **1250** (как 5 ячеек 3 уровня) |
  | 7 × 3 ур. | 2 радуги, как 5+      | 250 за клетку = 1750            |

- Две радуги встают в соседние клетки, поэтому их можно сразу поменять между собой —
  это комбо «радуга + радуга» (очистка поля).
- Ракета за линию из 4 ячеек 2 уровня бьёт вдоль линии (горизонтальная — строку, вертикальная —
  столбец) и встаёт в третью клетку группы — рядом с объединёнными ячейками. Квадрат 2×2 ракету
  не даёт.
- **Только в кампании** (`campaign` в `ResolveContext`; у `LevelSession` включён, у свободной игры нет,
  поэтому функцию на сервере это не меняет) — бомба 3×3 к обычной награде, в соседнюю клетку группы:
  - квадрат 2×2 из ячеек 2 уровня (кроме 2 ячеек 3 уровня);
  - группа из **6 и больше** фишек 1 уровня, в том числе фигура из 7 клеток (`CAMPAIGN_BOMB_GROUP`).
- **Только в кампании** — группа из **5 и больше ячеек 2 уровня** (любой формы) даёт спецфишки по размеру
  и ещё **2 ячейки 3 уровня**, очки — 50 за клетку (`CAMPAIGN_LEVEL2_PIECES`, `bigLevel2` в `resolve.ts`):

  | Группа ячеек 2 ур. | Награда                     | Очки                   |
  | ------------------ | --------------------------- | ---------------------- |
  | 5                  | мега-бомба + 2 ячейки 3 ур. | 250                    |
  | 6                  | радуга + 2 ячейки 3 ур.     | 300                    |
  | 7 и больше         | 2 радуги + 2 ячейки 3 ур.   | 50 за клетку (7 — 350) |

  Фигура из 7 клеток 2 уровня в кампании — как любые 7. Спецфишка встаёт на место награды, остальное —
  в соседние клетки группы, две радуги рядом. В свободной игре всё по таблицам выше.

- Совпадения 1 уровня спецфишек не дают. Бомба появляется из **покупки** и, в кампании, из квадрата 2×2 ячеек 2 уровня и группы 6+ фишек;
  ракета — из покупки и из линии 4 ячеек 2 уровня; манипулятор — только из покупки; мега-бомба — из совпадений
  5+ ячеек 2 уровня и 3 ячеек 3 уровня; радуга — из покупки, из совпадений 4+ ячеек 3 уровня
  и из фигуры из 7 клеток 2 уровня.

Все спецфишки рисуются картинками (`public/assets/pieces/<тип>.png`): бомба — бомба наполовину красная, наполовину чёрная (чтобы не путалась с красными фишками и мега-бомбой),
мега-бомба — чёрная, манипулятор — стрелки обмена, радуга — цветное кольцо, ракета — ракета
(по столбцу стоит вертикально, по строке — повёрнута набок).

**Все спецфишки бесцветные** (ракета, бомба, радуга, манипулятор, мега-бомба) и в совпадениях
не участвуют — они разрывают линии, как пустые клетки.

### Где появляется награда

- На ходе игрока — **в клетке, куда игрок передвинул фишку** (если она входит в группу;
  иначе — во второй клетке обмена).
- В каскаде и после активации тапом — в середине линии, у L/T — на пересечении,
  у квадрата 2×2 — в левой верхней клетке.
- Вторая ячейка или спецфишка (когда их 2) — в соседней клетке той же группы
  (порядок проверки: справа, слева, снизу, сверху).

### Активация спецфишек

- **Одиночное нажатие** взрывную спецфишку только выделяет и показывает подсказку,
  ничего не тратит.
  **Двойной клик** — два нажатия на одну клетку за 300 мс (`DOUBLE_TAP_MS`).
- **Ракета, бомба, мега-бомба** — два способа применить:
  - **двойной клик** — срабатывает **на месте** (**тратит ход**);
  - **сдвиг на любую соседнюю клетку** (обычную фишку или манипулятор; совпадение не нужно,
    **тратит ход**) — срабатывает **в клетке, куда переехала**. Если сдвинутая навстречу фишка
    собрала совпадение, **сначала срабатывает совпадение** (награда — в клетке этой фишки), потом
    взрыв; награду этого совпадения взрыв не задевает. Обмен с другой спецфишкой — комбо.
    Также срабатывают, когда задеты взрывом. Мега-бомба взрывается 5×5.
- **Радуга** — нажатие по ней → нажатие по любой фишке на поле: убираются все фишки этого цвета
  (любого уровня). **Тратит ход.** Нажатие по самой радуге отменяет выбор (быстрое второе
  нажатие двойного клика не отменяет). Если радугу задело
  взрывом — она сама убирает **самый частый цвет** на поле (при равенстве — цвет с меньшим индексом).
- **Манипулятор** — нажатие по нему → выбор двух любых клеток → они меняются местами.
  Совпадение не требуется, **тратит ход**, после использования манипулятор исчезает.
  Нажатие по самому манипулятору отменяет выбор (быстрое второе нажатие двойного клика не отменяет).
  Если манипулятор задело взрывом — он просто исчезает.
  Манипулятор можно **сдвинуть** на соседнюю фишку обычным обменом, если это даёт совпадение
  (свайпом или выбрав сначала фишку, а потом соседний манипулятор):
  он просто переезжает и остаётся на поле (ход тратится). Без совпадения обмен откатывается.
- Радугу можно **сдвинуть** на соседнюю фишку обычным обменом, если это даёт совпадение: она
  просто переезжает и остаётся на поле (ход тратится). Без совпадения обмен откатывается.
  С другой спецфишкой радугу можно поменять как комбо. Манипулятор в комбо не участвует.
- Задетые спецфишки срабатывают цепочкой.

### Комбо при обмене двух спецфишек

| Обмен                   | Результат                                                                               |
| ----------------------- | --------------------------------------------------------------------------------------- |
| Ракета + ракета         | Крест: строка + столбец                                                                 |
| Ракета + бомба          | 3 строки + 3 столбца                                                                    |
| Бомба + бомба           | Взрыв 5×5                                                                               |
| Радуга + ракета/бомба   | Фишки **самого частого цвета** превращаются в ракеты/бомбы и срабатывают                |
| Радуга + радуга         | Очистка всего поля                                                                      |
| Мега-бомба + ракета     | 5 строк + 5 столбцов                                                                    |
| Мега-бомба + бомба      | Взрыв 7×7                                                                               |
| Мега-бомба + мега-бомба | Очистка всего поля                                                                      |
| Мега-бомба + радуга     | Игрок тапом выбирает цвет; все фишки этого цвета превращаются в бомбы 3×3 и срабатывают |

- Центр комбо — клетка, куда игрок передвинул фишку.
- Превращаются **только фишки 1 уровня** этого цвета; ячейки 2–3 уровня не трогаются.
  Самый частый цвет считается по всем фишкам на поле (при равенстве — с меньшим индексом).
  Направление новых ракет — случайное.

### Уровни ячеек

- **Уровень 1** — обычные фишки, **2** и **3** — объединённые ячейки (см. «Совпадения: сразу
  награда»). Максимальный уровень — **3**.
- Объединённые ячейки совпадают **только с ячейками того же цвета и того же уровня**.
- Фишки — цветные фигуры. Цвета по порядку: синий, жёлтый, красный, зелёный, фиолетовый,
  оранжевый, голубой — сложность берёт первые N (см. «Меню и сложность»);
  уровень виден по форме: **1 уровень — круг, 2 — треугольник, 3 — пятиконечная звезда**.

### Очки

- Очки за совпадение — в таблице «Совпадения: сразу награда»: 1 уровень — 10 за клетку,
  2 уровень — 50 за клетку (группа из 5+ — 450 за всю группу), 3 уровень — 150 / 200 / 250
  за клетку в группе из 3 / 4 / 5+.
- Клетки, ушедшие в объединение, очки **дают**.
- **Комбо** — совпадение, собравшееся само после падения (и в свободной игре, и в кампании, и в финале,
  и после взрыва спецфишки). Первое такое за ход даёт очки ×1,1, второе ×1,2 и так далее, десятое ×2,
  дальше — ×2. Считается **каждая линия**: две в одном падении — ×1,1 и ×1,2. Совпадение, собранное
  самим ходом, множителя не получает, клетки под взрывом тоже. Счёт начинается заново с каждым ходом.
- Надпись «Комбо - x1.1» всплывает над совпадением (`view/comboLabel.ts`): шрифт VT323
  (`public/assets/fonts`), в нём нет кириллицы, поэтому м и б нарисованы по его сетке, а цвета
  (`COMBO_COLORS`) идут по кругу от жёлтого к красному через синий.
- Клетка, уничтоженная спецфишкой (не в совпадении): 1 уровень — 10, 2 уровень — ×5,
  3 уровень — ×15. Сами спецфишки очков не дают.

### Выбор игрока

- Сейчас совпадения выбора не требуют. Механизм выбора (шаг `choice`, диалог) оставлен в коде:
  если выбор вернётся, он показывается и на ходе игрока, и во время каскадов (каскад на паузе),
  а другие действия на поле в это время заблокированы.

### Партия: 35 ходов и финал

- Партия ограничена **35 ходами**. Рядом с очками — «Ходы: N»: **сколько ходов осталось**
  (35 → 0). Ход — всё, что его тратит (обмен, срабатывание спецфишки сдвигом или двойным кликом,
  манипулятор). Покупка спецфишки и перемешивание поля ходами не считаются.
- Когда 35-й ход завершился (вместе со своими каскадами), начинается **финал**:
  - **все спецфишки на поле срабатывают на месте** — ракеты, бомбы, мега-бомбы как обычно;
    **радуга** убирает **случайный** цвет из тех, что есть на поле; **манипулятор** просто
    исчезает и приносит **250 очков**;
  - затем — обычные падение, заполнение и каскады с очками; если в каскадах появились новые
    спецфишки, они тоже срабатывают, пока на поле не останется ни одной.
- После финала игра заканчивается: окно «Игра окончена» с очками и полем для имени
  (до **16 символов**; пустое — «Игрок»; в поле подставляется последнее введённое имя;
  поле сразу активно, а прошлое имя выделено — можно сразу печатать новое).
  После сохранения — **таблица лидеров** (10 лучших, строка игрока подсвечена; если результат
  в десятку не вошёл — об этом написано) этой сложности и кнопки **«Играть снова»** (та же
  сложность) и **«Меню»** (вернуться к выбору сложности).
- При равных очках выше тот, кто набрал их раньше.

### Покупка спецфишек за очки

- Над полем, под счётом, — кнопки спецфишек с ценой в очках:

  | Цена | Спецфишка                        |
  | ---- | -------------------------------- |
  | 150  | Бомба (взрыв 3×3)                |
  | 300  | Ракета (направление — случайное) |
  | 500  | Манипулятор                      |
  | 750  | Радуга                           |

- Кнопка, на которую хватает очков, подсвечена и пульсирует.
- Тап по доступной кнопке: **цена списывается со счёта** (было 600, купил бомбу — стало 450),
  спецфишка встаёт на место **случайной фишки 1 уровня** (фишка исчезает без очков).
  **Хода не тратит.** Покупать можно сколько угодно раз, пока хватает очков.
- Купить нельзя во время хода, выбора игрока и режимов радуги/манипулятора.
- Покупку **отменить нельзя**.

### Подсказка хода

- Если игрок **15 секунд** (`HINT_DELAY_MS`) ничего не нажимал, клетки самого сильного хода начинают
  пульсировать, а под полем появляется текст, что сделать. Касание экрана её убирает и запускает
  отсчёт заново; пока идёт ход или включён выбор радуги и манипулятора, отсчёта нет.
- Работает в свободной игре и на уровнях. Самый сильный ход (`core/hint.ts`) — наибольшие очки
  сразу, до падения новых фишек; на уровне к очкам прибавляется вклад в цели. Манипулятор
  подсказка не предлагает. **Спецфишку ради одних очков тоже не предлагает:** ход, который её тратит,
  подсказывается, только если цветная комбинация сдвинутой навстречу фишки даёт такую же спецфишку
  или (на уровне) сама продвигает задание. Взрыв в зачёт не идёт, поэтому двойной клик, радуга по цвету
  и комбо двух спецфишек не подсказываются; радуга и манипулятор, просто сдвинутые в совпадение,
  не тратятся и ограничению не подлежат. Если других ходов нет, подсказывается лучший из всех. Ход примеряется на копии поля и своём ГСЧ: ГСЧ партии трогать нельзя,
  иначе журнал разойдётся с проверкой на сервере.

### Шаг назад / шаг вперёд — убраны

- Кнопок отмены хода в игре нет. Тестовые стрелки «назад» и «вперёд» убраны;
  механизм истории (`core/history.ts`) и кнопка-стрелка (`ui/ArrowButton.ts`) пока остались
  в коде, если понадобятся снова.

### Кампания

- Режим уровней называется **«Кампания»**. Правила пяти обычных сложностей от неё не зависят:
  там покупка за очки, финал и таблица лидеров как раньше. В кампании финала и рейтинга нет.
- 10 этажей по 10 уровней: номер — этаж-уровень («2-7»), в `id` они идут подряд (2-7 — это 17).
- **Все уровни открыты сразу** (`ALL_LEVELS_OPEN` в `storage/progress.ts`, по просьбе владельца): проходить
  по порядку не нужно. Порядок открытия (`isLevelOpen` — нужен пройденный предыдущий) в коде остался:
  `ALL_LEVELS_OPEN = false` возвращает его. Карта открывается на этаже, до которого игрок дошёл по порядку.
- План кампании — `docs/campaign-plan.md` (поле и цели каждого уровня). Этажи: 1 — лёд (1 удар)
  и ячейки 3 уровня; 2 — сундуки, золото во льду; 3 — одна корона, ячейки 3 уровня цвета; 4 — уголь
  4–6 слоёв; 5 — лёд 2 уровня, сокровища в сундуках; 6 — сундуки в цепях, две короны; 7 — уголь
  6–8 слоёв; 8 — лёд с трещинами (3 удара); 9 — уголь 9 слоёв; 10 — всё сразу. Целей на уровне —
  до трёх: на местах 1–4 и 6–8 обычно одна, на 5 и 9 — две, на 10 — три. Поле — от 8×8.
- Поля — разной формы: буквы S, T, E, C, U, H, Z, восьмёрка, решётка, кольцо, крест,
  сердце, бриллиант и круг.
  Поле никогда не больше **10×10**. Цветов на поле **3**; 4 — редко и только на сплошном поле без дыр
  (сейчас это 1-9): так ячейки быстрее собираются до 3 уровня. Толщина линий — 4 клетки (у C левый столбец — 5, у U нижняя перекладина — 5 строк); полей меньше 8×8 нет; у E, 8 и S три перекладины 2/3/3 с
  просветами по 1 (основной столбец E — 5, столбцы 8 и S — по 4), у Z строки по 3 и диагональ шириной 6.
  Кольцо — 10×10 с дырой 2×2 ровно в центре. Уровни с целью на ячейки 2 уровня — на поле от 8×8.
  Лёд не кладётся в просветы тоньше 3 клеток и на край поля (у клетки льда со всех сторон клетки поля); сундуки — тоже не на краю. Сундуки в цепях стоят не ближе 3 клеток друг от друга
  (по строкам или столбцам, между ними минимум 2 клетки), в том числе по диагонали, и в одной строке
  больше одного такого сундука не бывает (в одном столбце — можно).

### Звёзды кампании

- Пройти уровень = выполнить цели. Звёзды: 1 за цели и по одной за 2 задачи из JSON уровня.
- Задачи на звёзды (`StarTask`) — по шаблону, очков в звёздах нет: **2★ — 10 ячеек 3 уровня, 3★ — 15**.
  Если цель уровня — сами ячейки 3 уровня (`level3` или `level3color`), звёзды — сверх неё: цель + 10
  и цель + 15 (`starTasks` в `scripts/tuneLevels.ts`). Задачи считаются как одноимённые цели.
  Код ещё понимает задачи `score`, `level2` и `item`, но в уровнях их нет.
- **Ячейки 2 уровня** (и цель, и задача на звезду): ячейка 3 уровня, собранная сразу из фишек 1 уровня
  в обход 2 уровня, засчитывается как **две** ячейки 2 уровня (`direct3` в шаге `transform`). Ячейки
  3 уровня считаются как обычно.
- **Купить спецфишку можно только на 10-м уровне этажа** (`LevelSession.shopOpen`): на остальных
  магазина нет совсем. Спецфишки из совпадений есть на всех уровнях.
- Спецфишки в кампании покупаются **за звёзды**, а не за очки:

  | Цена | Спецфишка   |
  | ---- | ----------- |
  | 3★   | Бомба       |
  | 5★   | Ракета      |
  | 5★   | Манипулятор |
  | 15★  | Радуга      |

- **Бомбу можно купить только одну за попытку уровня** (`CAMPAIGN_BONUS_LIMITS` в `core/config.ts`): после покупки
  кнопка гаснет. Остальные спецфишки — без ограничения, пока хватает звёзд.
- Покупка применяется **сразу и тратит ход**, на поле спецфишки не копятся. Звёзды списываются,
  когда выбрана цель; до этого покупку отменяет повторное нажатие на кнопку.
- **Бомба и ракета:** игрок выбирает клетку, и спецфишка срабатывает в ней. Можно только обычную
  фишку 1 уровня и не рядом по стороне со спецфишкой: так покупка не даёт дешёвое комбо.
  Запрещённые клетки затемняются, текстовой подсказки нет. Покупная ракета бьёт **только по строке**:
  вертикальная роняла бы корону на дно за один ход.
- **Радуга и манипулятор** на поле не ставятся: сразу выбирается цвет или две клетки.

- Кошелёк этажа = заработано на этом этаже − траты последних побед на его уровнях. Звёзды других
  этажей не считаются.
- Покупка не влияет на звёзды за уровень, а на карте у уровня они остаются.
- Потраченное на **проигранном** уровне возвращается (и если игрок ушёл с уровня): списание
  сохраняется только при победе. Повторное прохождение даёт только прибавку к лучшему результату.
- **Новая победа заменяет траты прошлой победы на этом уровне.** Победил дешевле — разница вернулась
  в кошелёк (без покупок вернётся всё); дороже — списывается только разница. **Повторная попытка
  начинается со звёздами, какие были до первой:** траты прошлой победы на этом уровне сразу
  возвращены и их можно потратить снова (`attemptWallet` в `storage/progress.ts`); на карте этажа
  кошелёк по-прежнему без возврата — он приходит в попытку.
- Траты, сделанные до появления этого учёта, записаны по этажам (`match3.floorSpent`) и не возвращаются.

### Препятствия кампании

- **Лёд** — слой под фишкой. Удар по нему — клетка очищена (клетке — один удар за шаг разбора хода). Виды (`ICE_HITS` в `core/config.ts`, картинка — `iceImage`
  в `view/obstacleArt.ts`):
  - **обычный** (`i`) — ломается с одного удара; рисуется той же картинкой, что лёд 1 уровня;
  - **лёд 2 уровня** (`J`) — весь новый лёд начинается с него (синие угловые грани — уровень виден
    из-под фишки). Удар превращает его в **лёд 1 уровня**, следующий ломает;
  - **лёд 2 уровня со слитками** (`g`) — снаружи такой же; после первого удара открывается
    **лёд 1 уровня со слитками золота**. Сломанный идёт в цель «золото»;
  - **спрятанное золото** (`hiddenGold` уровня) — слитки достаются случайным льдинам 2 уровня и сундукам
    (сокровища): например, из 60 льдин золото только в 20, остальные пустышки, и в каждой попытке в других;
  - **этап трещин** — `iceCracks: true` в JSON уровня, чтобы усложнить уровень: весь лёд 2 уровня
    получает ещё удар, лёд 1 уровня перед концом становится льдом с трещинами (простым или со
    слитками). Обычный лёд `i` этап не получает.
    В цель «лёд» идёт только сломанная целиком льдина любого вида, в том числе золотая. `levels:tune`
    добавляет и убирает лёд того вида, что уже на поле (`J` или `i`); лёд со слитками не трогает.
- **Камень** — падает вниз, как фишка, и закрывает собой клетку. Сдвинуть нельзя ни обменом, ни
  манипулятором, совпадение рядом не ломает, разбить — только взрывом, в том числе ракетой. Камень встаёт на камень.
  Перемешивание его не трогает.
- **Сундук** (бывшая коробка; в коде — `kind: 'box'`, `hitBox` в `core/board.ts`) — стоит на месте,
  фишки пролетают сквозь него, перемешивание его не трогает, сдвинуть и купить в него спецфишку нельзя.
  Удар — совпадение в соседней по стороне клетке или взрыв; за шаг разбора хода сундук получает один удар,
  сколько бы клеток совпадения его ни касалось. Стадии: **в цепях** (1–3 звена, каждый удар снимает
  звено; при 2–3 звеньях число видно в углу) → **закрытый** → **открытый** → исчезает. Открытый
  показывает, что внутри: сокровища или пусто. Сундук с сокровищами засчитывается в цель «золото»,
  когда сломан. Цель «сундуки» считает сломанные сундуки. Картинки — `public/assets/obstacles/chest-*.png`
  (из набора Freepik: бесплатная лицензия требует подписи «designed by Freepik», в игре её пока нет).
- **Цепи** лежат только на сундуках: фишек под цепью больше нет.
- **Корона** — падает и двигается как фишка: обмен, дающий совпадение, и манипулятор; перемешивание
  её не трогает (иначе само опускало бы её на дно). В совпадениях не участвует, разрушить её нельзя ничем. Засчитывается в самой
  нижней клетке столбца (дыры не клетки); камень или сундук на дне надо сначала убрать.
- **Уголь** — глыба 2×2 со слоями (`COAL_SIZE`) (`core/coal.ts`). Число слоёв задаёт уровень (`coalLayers`, 1–9,
  по умолчанию 9) — им подстраивается сложность. Стоит на месте; сдвинуть, перемешать, купить спецфишку
  в него нельзя. Совпадение, касающееся глыбы по стороне, снимает слои по уровню своих фишек: 1 уровень —
  1, 2 — 2, 3 — 3 (группа — один раз, сколько бы клеток ни касалось). Каждый взрыв, задевший глыбу
  (сработавшая спецфишка или зона комбо), снимает 1 слой; радуга по цвету угля не трогает. Слоёв
  не осталось — глыба исчезает, клетки заполняются. Очков удары не дают.
  - Фишки **не пролетают** сквозь уголь, а обтекают его (`settle` в `core/gravity.ts`): над глыбой
    ложатся на неё, новые падают только туда, куда сверху не мешает уголь; под глыбой фишки скатываются
    наискосок из соседних столбцов (пустые клетки снизу вверх, сначала сверху слева, потом справа),
    а куда скатиться нечему (строка сразу под глыбой, кроме крайних столбцов) — новые фишки появляются
    прямо на месте. Без угля падение прежнее, поэтому свободная игра от этого не меняется.
  - Картинки — `public/assets/obstacles/coal-1.png` … `coal-9.png`: глыба всегда начинается с самой большой
    картинки (стадия 1), последний слой — стадия 9, между ними стадии делятся поровну по доле снятых слоёв
    (`view/coalStage.ts`; у глыбы из 3 слоёв — 1, 5, 9), с каждой стадией глыба меньше. В строке целей виден остаток:
    «Уголь 0/1 (слоёв 5)».

### Цели уровней

- Создать N ячеек нужного уровня, мега-бомб или радуг; собрать N ячеек 3 уровня одного цвета
  (`level3color`, у цели поле `color` — индекс в палитре; «Собери 5 синих звёзд», «Синие звёзды 2/5»);
  сломать N льдин, камней или сундуков;
  опустить на дно N корон; разбить N глыб угля; достать N золота (сломать лёд со слитками или сундук
  с сокровищами). Уровень может сочетать несколько целей;
  ходы кончились раньше, чем они выполнены, — поражение. **Выполнил цели — победа засчитана, но уровень
  не кончается:** он идёт, пока не выполнены все задачи на звёзды (очки и ячейки) или не
  кончились ходы — иначе досрочный конец отнимал бы шанс на три звезды (`LevelSession.isOver`).
- **Финал кампании:** уровень кончился — ходами или досрочно на трёх звёздах, — а на поле остались
  спецфишки: они срабатывают по одной
  (`LevelSession.campaignFinale`), и итог подводится уже после финала: финал может доломать лёд,
  сундуки, собрать нужные ячейки и превратить поражение в победу. Каждый раз срабатывает та спецфишка,
  что сильнее всего улучшит итог: сначала выполнить задание, потом приблизить его, потом звёзды,
  потом очки (при трёх звёздах — значит, только очки). Ход примеряется на копии партии своим ГСЧ. Радуга выбирает лучший цвет, манипулятор —
  лучший обмен (без полезного просто уходит); спецфишки из каскадов финала тоже идут в дело.
  Боты играют финал так же, поэтому замеры его учитывают.
- **Лишних препятствий нет:** льда и сундуков на поле ровно столько, сколько требует цель
  (иначе у игроков чувство незавершённости). `levels:tune` меняет цель вместе с полем: растёт цель —
  добавляет препятствия по правилам выше (снизу вверх, зеркальными парами; сундуки в цепях — новыми, потом
  звеньями до трёх; сундуки с сокровищами и лёд со слитками не трогает), уменьшается — убирает сверху (`scripts/levelLayout.ts`).
  Камни — помеха: в цели не входят и остаются на поле.
- **Короны:** на поле одна (лёгкие уровни) или две (сложные), цель — все короны поля, «Короны 1/2».
  Корона стоит **не ниже середины поля**: снизу её доводят за пару ходов. Уголь в столбцы корон не ставится: глыба держала бы корону, пока не разбита. Уголь вместе со льдом или коронами — 2–3 глыбы, этап трещин — только на 5, 9 и 10 местах этажа: иначе такие уровни не проходились и с малыми целями. На лёгких местах
  этажа у сундуков не больше одного звена цепи.
- На экране уровня: заголовок — только номер «1-10» (название из JSON не показывается), рядом с очками кошелёк этажа, строка прогресса
  целей (не влезает в ширину поля — переносится на вторую строку по целям, затем мельче шрифт) и под ней условия
  всех трёх звёзд (`levelBriefing`; отдельной строки «Задание» нет — цели видны в строке прогресса). У каждой звезды там же
  виден прогресс, он обновляется по ходу партии: «★ Собрать 18 ячеек 3 уровня — 5/18», выполненная —
  «— готово».

### Сложность уровней

- Кривая владельца — одна на все этажи, доля **поражений** опытного бота по местам на этаже:
  1–4 — около 10%, 5 — 45–55%, 6–8 — около 10%, 9 — 45–55%, 10 — 85–95% (`WIN_CURVE`: 90, 90, 90, 90,
  50, 90, 90, 90, 50 и 10% побед). Покупки бота: на местах 1–4 и 6–8 — никаких, на 5 и 9 — одна бомба
  (только в замере: игроку магазин там не открыт), на 10 — любые за 20 звёзд. 10-е место с покупкой спецфишек
  за звёзды (бот `buyer`, 20 звёзд — `BOSS_WALLET`, бомба одна за попытку) — 50–70% поражений, то есть
  30–50% побед (`BOMB_WINS`).
- `npm run levels:tune -- <партий> <этаж>` проигрывает уровни без лимита ходов, подбирает размер целей
  так, чтобы на уровень уходило задуманное число ходов (`MOVES_CURVE`: от 25 на 1-м месте до 40 на
  10-м), и выставляет ходы (25–45: больше игроку не даём) под кривую, звёзды — по шаблону 10/15. Уровни, которые не попадают в кривую,
  он помечает «мимо кривой». На 10-м месте размер целей (у угля — слои, `coalLayers`) подбирается
  так, чтобы с двумя бомбами побед было 30–50%; вне окна — «мимо окна».
  На уровнях только с коронами рычаг — высота корон: подгонщик опускает их по столбцам (дыры пропускаются,
  ниже середины поля и на занятую клетку корона не встаёт — `lowerCrowns`), пока уровень не уложится
  в задуманное число ходов; с другими целями сначала опускаются короны, потом подбираются остальные цели.
  На первом этаже лёд — главная цель (20–25 льдин на лёгких местах, 35–40 на 5, 9 и 10) и не меняется, если у уровня есть другие цели.
  Спрятанное золото меняется вместе со льдом 2 уровня и сундуками, где оно прячется. `--keep-moves` не трогает цели и ходы, `--only=9,10` —
  подгоняет только эти места этажа.
  Посмотреть итог — `npm run levels -- <партий> [этаж]`. Поменял правила или поле — подгони снова.
- **Мастерство бота подобрано по живым игрокам** (`botSkill.attention` в `scripts/levelBots.ts`): за ход он замечает
  в среднем 2,25 случайных обмена (спецфишки — всегда). Ещё до 3 обменов он замечает рядом с отдельными предметами цели — коронами, сундуками, углём, камнями (`botSkill.focus`): человек ищет ходы у них нарочно. Лёд в счёт, только когда клеток цели на поле не больше 12 (`FOCUS_TARGETS`): несколько льдин видны сразу, а разбросанные по всему полю — нет. Без этого бот не проходил и минимальные цели с коронами и углём. Обмены в 1–3 клетках прямо под короной он видит всегда (`CROWN_LOOK`): застрявшую корону человек высматривает нарочно. Шаг короны вниз ценится по оставшемуся пути до дна (`crownDistance`): доставленная корона уходит с поля, и счёт по строкам корон штрафовал бы бота за доставку. На уровнях, которые люди играли (1-1 и 1-5 версии `bfbbcb8`),
  так у бота 39% и 13% побед, у людей — 38% (3 из 8) и 6% (1 из 17). Пересчитать — `vite-node scripts/calibrateBot.ts
  <партий> <внимание> <уровень.json>… [--focus=N]` на версиях уровней из `level_results`; данных станет больше — уточни.
- **Калибровка по ходам людей** (`npm run levels:humans`): попытки из `level_moves` проигрываются заново, и в каждой
  позиции видно, как часто бот вообще замечает ход человека и с какой вероятностью сделал бы его сам; `--grid`
  подбирает внимание, фокус и температуру по правдоподобию ходов людей. **Температура** (`botSkill.temperature`)
  — выбор хода через softmax: из лучших 6 примеренных ходов (`weighMoves`) бот берёт ход тем чаще, чем он ценнее;
  0 — всегда лучший (так подогнаны уровни сейчас). Ходов людей пока нет; поменял параметры по ним —
  подгони уровни заново. `--synthetic=<партий> --levels=1,5 --true-t=N` проверяет сам способ на «людях»-ботах.
- Опытный бот видит на один ход вперёд, как человек: перебирает сначала ходы рядом с коронами
  и оставшимися препятствиями цели, лучшие 6 примеряет целиком, с каскадами (`LevelSession.trial`), и к каждому
  добавляет лучший следующий ход (вполовину веса). Дальше не смотрит. Где спрятано золото, он не знает,
  пока лёд или сундук его не покажет: до того ценит удар по надежде (сколько золота осталось на сколько мест).
  Для замера бомбы на 5-м и 9-м местах магазин открывается только боту (`anyShop` у `LevelSession`).
- Бот с покупками (`buyer`) выбирает лучшую клетку и покупает, когда это полезнее лучшего обычного хода;
  манипулятор он не применяет.
- **Журнал бота** — `stats/bot-runs.jsonl` (замеры) и `stats/level-versions.jsonl` (поля и цели каждой
  версии уровня), ведёт их `scripts/botStats.ts`. Только бот: живые игроки — в `level_results`.
  Сначала смотри сюда, а не считай заново: `npm run levels` берёт готовый замер, если не менялись
  ни уровень, ни логика (`src/core`, боты). Новые строки коммить вместе с уровнями.
  Файлы — в репозитории, потому что данные не секретны и их читает агент без помощи владельца;
  репозиторий публичный, поэтому **ключей в него не класть**. В сборку игры `stats/` не попадает.
  Откат уровня: `npm run levels:history -- 4-10 <хеш>`, затем проверки и коммит.

## Первая версия включает

- Все правила выше.
- **Карта уровней** и **1–3 звезды** за прохождение.

## Данные

- **Уровни** — JSON-файлы в `src/levels/floorNN/` (`01.json` … `10.json`), проверяются
  при загрузке (`parseLevel` в `core/level.ts`). Поле — строки: `.` клетка, `#` дыра, `i` лёд,
  `J` лёд 2 уровня, `g` лёд 2 уровня со слитками золота (этап трещин — `iceCracks`),
  `s` камень, `b` сундук, `t` сундук с сокровищами, `o` корона, `1`–`3` сундук в цепи из стольких звеньев,
  `u` / `v` / `w` сундук с сокровищами в цепи из 1 / 2 / 3 звеньев,
  `c` уголь (только квадраты 2×2; слоёв — поле `coalLayers`).
  `hiddenGold` — сколько золота спрятать в случайные льдины `J` и сундуки без сокровищ (`b`, `1`–`3`):
  где оно, решает seed попытки (свой ГСЧ, поле фишек не меняется), остальные — пустышки.
- **Прогресс игрока** (лучшие звёзды и траты по уровням, настройки) — `localStorage`.
  Доступ к нему обёрнут в try/catch: игра должна работать, даже если хранилище недоступно.
- **Запросы к Supabase — без предварительного запроса CORS** (быстрее на один запрос): ключ чтения —
  в адресе (`?apikey=`), к функции — `POST` без своих заголовков. Исключение — `game_results`.
- **Известная проблема:** на части телефонов (Android, Chrome, Wi-Fi) запросы из игры к адресу
  `*.supabase.co` висят без ответа, хотя другие сайты отвечают; игра тогда пишет «Нет связи».
  Причина в соединении, а не в CORS: простые запросы висят так же, а до Supabase они не доходят
  (нет в журналах). Причина точно не установлена: похоже на известное ограничение Cloudflare
  в России (соединение замирает примерно после 16 КБ), Supabase работает через Cloudflare. На одном
  соединении первые запросы проходят, следующие зависают; повторная попытка иногда проходит, поэтому
  игра сама обрывает зависшие запросы и повторяет их (`withRetries`): чтение 4 раза по 4 с, билет
  3 раза по 8 с. Запись результата не повторяется — билет гасится один раз; вместо этого перед ней
  идёт чтение, которое поднимает соединение. Проверка — `public/diag.html`.
- **Общая таблица лидеров** — в Supabase (таблица `public.leaderboard`; схема и правила доступа —
  `supabase/leaderboard.sql`). Игра ходит в REST API напрямую (`src/storage/remoteLeaderboard.ts`),
  адрес и **публичный** ключ (`sb_publishable_…`) берутся из `.env` (`VITE_SUPABASE_URL`,
  `VITE_SUPABASE_KEY`). `.env` лежит в репозитории: ключ публичный, права ограничены правилами
  базы. Секретный ключ (`sb_secret_…` / `service_role`) в проект не кладётся никогда.
  - **Из браузера таблицу можно только читать.** Записывает только серверная функция
    (`src/server/gameServer.ts`, Edge Function `smooth-handler`; права — `supabase/verified_results.sql`,
    выполняется шестым). Перед партией функция выдаёт билет со случайным seed (таблица
    `game_sessions`, сцена получает его через `src/scenes/startGame.ts`), в конце принимает
    журнал действий (`GameSession.actions`), сама проигрывает партию (`replayGame` из
    `src/core/session.ts`) и записывает посчитанные ею очки — браузер очков не передаёт.
    Билет работает один раз, живёт сутки и не раньше чем через 10 с после выдачи; с одного IP —
    до 30 билетов в минуту. Журнал с недопустимым действием отклоняется: «Результат не прошёл
    проверку». Секретный ключ функция берёт из своего окружения в Supabase, в проекте его нет.
    Запись идёт с адреса сервера, поэтому IP игрока функция передаёт явно (`app.client_ip`).
    Функция развёрнута без проверки JWT: ключи `sb_publishable_` — не JWT.
    Обойти это нельзя подделкой запроса, но бот, играющий настоящими ходами, пройдёт.
    Без связи или с `?seed=` партии нет билета: результат остаётся только на устройстве.
    Владелец может добавить запись вручную в SQL Editor: проверка её не касается.
  - **Частая отправка** (`supabase/shared_ip.sql`, выполняется пятым; основа — `rate_limit.sql`).
    За одним IP бывает целая организация, поэтому две партии подряд с него — норма:
    до 10 отправок в минуту принимаются, сверх этого лишние отбрасываются (остальные записи
    не трогаются). 60 отправок за 10 минут — спам: IP блокируется на сутки (таблица
    `leaderboard_bans`), удаляются только его записи за эти 10 минут. Отклонённая запись
    не вызывает ошибку (иначе база откатила бы удаление), а отдаёт пустой ответ — игра пишет
    «Результат не принят: слишком частая отправка». IP хранится в столбце `ip`, из браузера
    его не прочитать. Снять блокировку — удалить строку из `leaderboard_bans`.
  - **Только десятка** (`supabase/top10.sql`, выполняется третьим): в базе хранятся лишь
    10 лучших записей на сложность — после каждой новой записи выпавшие из десятки удаляются.
    Частота отправки проверяется по отдельному журналу `leaderboard_submissions`
    (IP и время, хранится сутки), а не по самой таблице: слабый результат сразу удаляется,
    и иначе повторную отправку было бы не заметить.
  - **Архив** (`leaderboard_archive`, из `shared_ip.sql`): всё, что уходит из таблицы лидеров,
    копируется сюда на 90 дней; из браузера недоступен. Записи, удалённые до появления архива,
    можно вернуть только из локальных таблиц: `supabase/restore_from_browser.js` собирает
    из `localStorage` компьютера игрока SQL для вставки.
- **Все доигранные партии** — анонимно, для анализа: таблица `public.game_results` в Supabase
  (`supabase/game_results.sql`, выполняется четвёртым). Игра отправляет запись сразу после
  финала, ещё до ввода имени (`src/storage/gameResults.ts`, статистика копится в
  `src/core/gameStats.ts`). Поля: сложность, очки, ходы, длительность (с первого хода), очки
  финала, перемешивания, созданные ячейки 2/3 уровня, спецфишки из совпадений и сработавшие,
  покупки по видам и потраченные очки, устройство (touch/desktop), размер экрана, версия
  (коммит; в сборке на GitHub — `VITE_GAME_VERSION`, локально — `dev`).
  - Имени и IP нет. Из браузера — только добавление, читать — в Supabase. Эти данные сервер
    не проверяет, их можно подделать; на таблицу лидеров это не влияет.
  - С одного IP — до 10 записей в минуту (журнал `game_results_submissions`, лишнее молча
    отбрасывается); IP из `leaderboard_bans` сюда не пишут. Ошибка отправки игре не мешает.
  - **Попытки уровней кампании** — анонимно, таблица `public.level_results` (`supabase/campaign.sql`,
    выполняется седьмым; `src/storage/levelResults.ts`). Запись на победу, поражение и уход на карту
    после первого хода (закрытую вкладку записать нельзя). Поля: уровень, исход, звёзды, ходы, процент
    целей, перемешивания, длительность, покупки и потраченные звёзды, устройство, экран, версия.
    Имени и IP нет. С одного IP — до 60 записей в минуту, лишнее молча отбрасывается.
    Сходимость с ботом проверяйте здесь: настоящая сложность видна только по живым игрокам.
  - **Ходы попыток уровней** — анонимно, таблица `public.level_moves` (`supabase/level_moves.sql`,
    выполняется восьмым; `src/storage/levelMoves.ts`). Отправляется вместе с `level_results`: уровень, версия игры,
    seed попытки, звёзды этажа на её начало и журнал (`LevelSession.journal` — ходы и покупки: `aim` — покупная
    бомба или ракета в клетку, `pay` — оплата радуги или манипулятора). По ним попытка проигрывается заново
    (`replayLevel` в `core/levelReplay.ts`). Отдельная таблица, чтобы итоги попыток писались, даже пока её нет.
    С одного IP — до 60 записей в минуту. Имени и IP нет.
  - При открытии меню игра будит функцию простым запросом (`wakeGameServer`): после простоя
    на бесплатном тарифе её первый ответ занимает секунды, а так их не ждёт запуск партии.
  - В меню у сложности — общий рекорд (все рекорды — одним запросом, `fetchRecords`): очки и имя
    игрока. Пока сервер не ответил, виден рекорд
    этого устройства; когда ответил — только общий (если общих записей нет — пусто), чтобы
    на всех устройствах меню показывало одно и то же.
  - Без `.env` или без билета показывается таблица этого устройства с подписью «Нет связи —
    результаты этого устройства». Нет ответа на запись — «Нет ответа сервера — результат мог
    сохраниться»: ответ теряется и после записи. Запись прошла, а таблица не прочиталась —
    «Результат сохранён, таблица не загрузилась».
- **Перенос прогресса** — кнопка на карте кампании (`ui/TransferDialog.ts`, `storage/transfer.ts`).
  Прогресс живёт в браузере, на сервере — только копия по коду из 8 символов (таблица
  `progress_transfers`, функции `save_progress` и `load_progress`, `supabase/campaign.sql`). Из браузера
  таблицу не прочитать, можно только вызвать функции, зная код. Код один на игрока и живёт год с
  последнего использования. Копии складываются: от каждого уровня берётся большее, поэтому
  устройство с меньшим прогрессом ничего не затирает; траты на уровне при этом тоже берутся
  большие, так что возврат с другого устройства не перенесётся. Сохранить — до 10 раз, загрузить — до 20 раз в минуту с IP.
  Вызов функций базы идёт с `Content-Type` и предварительным запросом CORS. Вход не нужен,
  поэтому потерянный код не вернуть, а знающий код может его использовать.
- **Локальные таблицы лидеров** (по одной на сложность, 10 лучших) и последнее имя игрока —
  `localStorage` (`src/storage/leaderboard.ts`), по тем же правилам. Результат всегда пишется
  и сюда — как запасной вариант.

## Архитектурные правила

1. **`core/` не зависит от Phaser, DOM, таймеров.** Вся логика тестируется без браузера.
2. **Логика возвращает шаги, вид их анимирует.** `resolveMove` — генератор, который отдаёт шаги
   `swap`, `clear`, `transform`, `drop`, `choice`. На шаге `choice` он останавливается, пока сцена
   не передаст выбор игрока через `next(option)`. В тестах ход прогоняется через `runMove`.
3. **Детерминизм:** вся случайность — через `core/rng.ts` с seed, без `Math.random()` в `core/`.
4. Ввод блокируется во время анимаций и ожидания выбора.
5. Координаты `row` (сверху вниз) и `col`; поле — `cells[row][col]`, пустая клетка — `null`,
   дыра в поле — отдельный тип клетки.
6. Все числа (множители, размеры взрывов, длительности анимаций) — в `core/config.ts`.

## Тесты

- Каждое правило игры покрыто тестом в `tests/core/`, особенно: формы совпадений, объединение
  по уровням, выбор игрока в каскадах, спецфишки, цели уровней.
- Поля в тестах задаются строковой нотацией (цвет + уровень), например:
  ```ts
  const board = parseBoard(`
    R1 R1 G1
    B2 B2 B2
    G1 R3 G1
  `);
  ```
  Спецфишки: `-` / `|` — ракета по строке / столбцу, `*` — бомба, `@` — радуга,
  `M` — манипулятор, `X` — мега-бомба; `.` — пусто, `#` — дыра.
  В JSON уровня поле — строки символов: `.` клетка, `#` дыра, `i` лёд (`J` — 2 уровня,
  `g` — со слитками золота), `s` камень, `b` / `t` сундук (с сокровищами), `1`–`3` / `u`–`w` он же в цепи из 1–3 звеньев, `o` корона, `c` уголь (глыба 2×2).
- Для случайных сценариев — фиксированный seed.
- Для ручной проверки в браузере: `?seed=N` в адресе даёт одинаковое поле (без общей таблицы),
  а в dev-режиме
  из консоли доступно `window.gameScene.debugSetBoard(board)`, а `window.game` — сама игра
  (`game.scene.start('Game', { level })`, `game.step(...)` — кадры, когда панель браузера скрыта).
- Баг в логике → сначала падающий тест, потом исправление.

- Идентификаторы в коде — **английский**.

## Стиль кода

- TypeScript strict, без `any`.
- Небольшие чистые функции в `core/`.
- Комментарии объясняют «почему», а не «что».

## Правила для агента

- **Не меняй правила игры сам.** Любое изменение механики — только после согласования
  с пользователем. Если правило не описано или неоднозначно — спроси, а не додумывай.
- **Коммить самостоятельно** после каждого завершённого шага, когда проходят тесты, линтер
  и проверка типов. Сообщение коммита — кратко, по-русски, о сути изменения. Не пушь без просьбы.
- Работай небольшими шагами; перед крупным изменением кратко опиши план.
- Если меняешь структуру, команды или правила — обнови этот файл.
- Визуальную часть проверяй через `npm run dev` в браузере, в том числе в мобильном размере экрана.
